Module 1 · Search Engine Core LIVE INDEX

The Inverted Index

A forward index maps documents to the words they contain. Flip that relationship and you get an inverted index: a hash map from every normalized term to the list of documents containing it. Looking up a term becomes an O(1) hash lookup instead of an O(n) scan across every document.

index["search"] = [ { docId: 1, tf: 0.045, count: 2, positions: [4, 41] }, { docId: 9, tf: 0.028, count: 1, positions: [3] }, ... ]

Each posting stores the document id, the term frequency (tf), the raw count, and the token positions — enough data to rank results and highlight matches without re-reading the document.

TF · IDF Ranking

Term Frequency measures how often a term appears relative to document length. Inverse Document Frequency down-weights terms that appear in nearly every document, since they carry little distinguishing signal.

TF(t, d) = count(t, d) / totalTerms(d) IDF(t, D) = log( |D| / (df(t) + 1) ) + 1 Score(d,Q) = Σ TF(t, d) × IDF(t, D) for each t in Q

The engine sums the TF-IDF weight of every query term for each candidate document, then sorts descending. Try a query on the right and switch to Score Breakdown to see these numbers computed live.
